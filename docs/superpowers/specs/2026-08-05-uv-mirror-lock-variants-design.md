# UV Mirror Lock Variants Design

**Date:** 2026-08-05

**Status:** Approved for specification by the user; implementation requires a separate plan and review

**Scope:** Strict, reproducible `uv` environment bootstrap with PyPI, Tsinghua, and Aliyun source failover

## 1. Problem and measured evidence

The profile orchestrator currently imports `PYPI_INDEX` from `mirrors.env` into
`UV_INDEX_URL` before it runs `uv sync --locked --all-groups`. A global
`UV_INDEX_URL` can also be inherited when `mirrors.env` does not yet exist.
Both paths can make the active index disagree with the registry URLs recorded
in `uv.lock`.

The failure was reproduced on the target Windows machine:

- inherited environment: `UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple`;
- `uv lock --check` against the committed PyPI lock exited non-zero;
- the same check with the default index or explicit
  `https://pypi.org/simple` exited zero;
- relocking a temporary copy against Tsinghua preserved package versions and
  hashes but rewrote registry and artifact URLs throughout the lock;
- a fresh resolution configured with Tsinghua, Aliyun, and PyPI locked all 75
  registry packages to Tsinghua, the first index containing them. Aliyun did
  not become a runtime fallback.

This matches uv's documented model: project lockfiles are generated and
managed by uv, each registry package has one selected source, and multiple
indexes are consulted in priority order during resolution. A single package
entry cannot contain interchangeable mirror registries.

## 2. Goals

1. Keep exact dependency versions, markers, dependency edges, and artifact
   hashes locked.
2. Support real source failover in the order PyPI, Tsinghua, then Aliyun.
3. Keep the repository clean during bootstrap; formal-profile clean-tree gates
   must not observe a transiently replaced root lockfile.
4. Ignore unrelated global uv index configuration during orchestrated sync and
   restore the caller's environment afterward.
5. Fail closed when lock variants diverge semantically or no source can
   provide the locked environment.
6. Record which source and lock hash provisioned the environment.
7. Preserve the existing `uv sync --locked --all-groups` contract; do not
   weaken it to `--frozen` or an unlocked resolution.

## 3. Non-goals

- Do not invent unsupported fields inside `uv.lock`.
- Do not change package versions or dependency constraints as part of mirror
  support.
- Do not make Tsinghua or Aliyun authoritative over PyPI metadata.
- Do not add general-purpose private-index or credential management.
- Do not change dataset, model, GitHub, CTAN, or WSL mirror behavior except for
  ordering the existing mirror stage before Python environment sync.

## 4. Lock catalog

The committed catalog is:

```text
uv.lock                       # canonical PyPI lock
locks/uv.tuna.lock            # Tsinghua registry/artifact URLs
locks/uv.aliyun.lock          # Aliyun registry/artifact URLs
locks/manifest.json           # source URLs, lock hashes, normalized graph hash
```

The root `uv.lock` remains the canonical dependency-resolution record used by
normal developer commands and CI. The two mirror variants are generated by uv
from the same `pyproject.toml` and the canonical lock's existing preferences;
they are not edited by string replacement.

`scripts/generate-uv-lock-variants.ps1` will create each variant in an isolated
temporary project using the corresponding `--default-index`. It will not use
`--upgrade`. For each mirror, the exact generation sequence is:

1. create a new external temporary project;
2. copy the repository `pyproject.toml` and canonical `uv.lock` into it;
3. clear the controlled uv environment variables defined in section 7;
4. run `uv lock --no-config --project <temp> --default-index <mirror-url>`
   without `--upgrade` so the canonical pins are resolution preferences;
5. run the same command with `--check` and retain the resulting temporary lock.

The canonical PyPI lock is separately checked with:

```powershell
uv lock --check --no-config --project <canonical-temp> `
  --default-index https://pypi.org/simple
```

The generator then verifies the complete staged three-lock set and creates
this deterministic manifest (no timestamp):

```json
{
  "schema_version": 1,
  "normalized_graph_sha256": "<64 lowercase hex>",
  "locks": {
    "pypi": {
      "path": "uv.lock",
      "index_url": "https://pypi.org/simple",
      "artifact_url_prefix": "https://files.pythonhosted.org/packages/",
      "sha256": "<hex>"
    },
    "tuna": {
      "path": "locks/uv.tuna.lock",
      "index_url": "https://pypi.tuna.tsinghua.edu.cn/simple",
      "artifact_url_prefix": "https://pypi.tuna.tsinghua.edu.cn/packages/",
      "sha256": "<hex>"
    },
    "aliyun": {
      "path": "locks/uv.aliyun.lock",
      "index_url": "https://mirrors.aliyun.com/pypi/simple",
      "artifact_url_prefix": "https://mirrors.aliyun.com/pypi/packages/",
      "sha256": "<hex>"
    }
  }
}
```

The manifest and lock objects reject missing or unknown fields. After the full
staged set passes, the generator creates backups and performs individual
same-volume atomic file replacements for the two variants and manifest. If a
replacement fails, it restores every original from the backups before exiting.
The canonical root lock is never replaced.

## 5. Semantic-equivalence gate

`scripts/verify_uv_lock_variants.py` will parse the locks with Python's TOML
parser and calculate a normalized graph digest. The manifest deliberately keeps
the PEP 503 `index_url` separate from `artifact_url_prefix`: PyPI resolves from
`pypi.org/simple` but downloads from the `files.pythonhosted.org` CDN, while the
two mirrors expose the measured prefixes shown above. URL validation requires
HTTPS, lower-case scheme and host, no user information, query, or fragment, and
the exact manifest path form. For registry packages, normalization replaces an
exact approved `source.registry` with the token `<registry>` and compares each
artifact by decoded filename, SHA-256, and declared size instead of its mirror-
specific URL. Non-registry, Git, path, and direct URLs remain byte-for-byte
significant. It retains and compares:

- lock schema version, revision, Python requirement, and resolution markers;
- every package name, version, source kind, dependency, optional dependency,
  marker, and conflict declaration;
- sdist and wheel filenames plus SHA-256 hashes;
- the virtual root package version and dependency groups.

Every registry source must equal that file's declared `index_url`; every sdist
and wheel URL must begin with that file's separate `artifact_url_prefix` and
contain a non-empty relative path. Aliases and mixed trailing-slash forms are
rejected rather than silently normalized as additional sources.
The normalized graph digests of all three locks must be identical. Unknown
registries, missing artifacts, changed hashes, changed package versions, or a
mixed-source variant fail the gate.

The verifier is deterministic and does not require network access. It runs in
the test suite and release gate. The generation script additionally runs
`uv lock --check` against each variant and its matching index while generating
or explicitly refreshing variants.

## 6. Source detection and selection

`scripts/detect-mirrors.ps1` will probe these PEP 503 roots independently:

1. `https://pypi.org/simple`
2. `https://pypi.tuna.tsinghua.edu.cn/simple`
3. `https://mirrors.aliyun.com/pypi/simple`

It will retain `PYPI_INDEX=<first reachable URL>` for existing downstream
consumers and atomically write a generated, gitignored `mirrors.json` with this
exact schema:

```json
{
  "schema_version": 1,
  "network_status": "ok",
  "uv_indexes": [
    {"id": "pypi", "url": "https://pypi.org/simple", "priority": 0, "reachable": true},
    {"id": "tuna", "url": "https://pypi.tuna.tsinghua.edu.cn/simple", "priority": 1, "reachable": true},
    {"id": "aliyun", "url": "https://mirrors.aliyun.com/pypi/simple", "priority": 2, "reachable": true}
  ]
}
```

`network_status` uses the existing `ok`, `degraded`, or `offline` vocabulary.
All three entries are always present; `reachable` carries the probe result.
The consumer requires exactly the documented top-level and entry fields,
canonical URLs, IDs, priorities, and array order. It rejects duplicates,
unknown fields or IDs, non-HTTPS URLs, aliases, and type mismatches before uv
runs. The profile orchestrator maps the stable IDs through the tracked lock
manifest and never maps an arbitrary inherited URL to a lock.

The `environment.mirrors` stage moves before `environment.python`. This makes
source selection explicit on a clean checkout instead of accidentally relying
on a stale file or parent-process environment.

## 7. Isolated sync flow

For each reachable candidate in order, `scripts/reproduce.ps1` will:

1. resolve the candidate to its tracked lock and expected index URL;
2. validate the selected lock SHA-256 against `locks/manifest.json` using
   PowerShell before any environment mutation;
3. create a unique repository-external temporary project;
4. copy `pyproject.toml` and the selected variant as temporary `uv.lock`;
5. set `UV_PROJECT_ENVIRONMENT` to the real repository `.venv`;
6. snapshot whether each controlled process variable is absent or present and,
   when present, its exact value; then clear `UV_INDEX`, `UV_DEFAULT_INDEX`,
   `UV_INDEX_URL`, `UV_EXTRA_INDEX_URL`, `UV_INDEX_STRATEGY`, `UV_NO_INDEX`,
   `UV_FIND_LINKS`, `UV_CONFIG_FILE`, and `UV_NO_CONFIG`;
7. invoke the following command:

   ```powershell
   uv sync --locked --all-groups --no-config `
     --project <temporary-project> `
     --default-index <selected-url> `
     --index-strategy first-index
   ```

8. run the full Python semantic-equivalence verifier immediately after the
   first successful sync and before any later reproduction stage;
9. restore `UV_PROJECT_ENVIRONMENT` and every controlled variable in `finally`,
   preserving the distinction between absent and present-with-empty-value;
10. remove only the validated task-owned temporary directory.

The root `uv.lock` hash and git status are sampled before and after sync. Any
change is a hard failure. The pre-sync manifest check makes bootstrap possible
without an existing Python environment; the post-sync semantic check defends
against a stale or incorrectly generated manifest before inference begins.
Unique external temporary directories make parallel checkouts safe and keep
formal clean-tree checks meaningful.

If a reachable source cannot complete the locked download/sync, the
orchestrator records its exit code and concise error, then tries the next
semantically equivalent lock. A later source is allowed to complete a partial
environment left by an earlier transport failure because the final exact sync
still enforces the selected lock. If every candidate fails, the stage reports
all attempted source IDs and exits non-zero. It never falls back to unlocked
resolution.

## 8. Provenance and resume behavior

After successful sync, the orchestrator writes an environment-lock record
under the profile evidence directory containing:

- selected source ID and URL;
- selected lock path and SHA-256;
- canonical normalized graph SHA-256;
- `pyproject.toml` SHA-256;
- uv version and completion timestamp;
- failed candidates attempted before success.

The selected source is provenance, not a semantic model input. When
`inputs.fingerprint` constructs `fingerprint.provisioning.spec.json`, it keeps
the existing canonical `uv_lock_sha256` input and adds
`uv_normalized_graph_sha256 = @{ string =
$lockManifest.normalized_graph_sha256 }`. It does not fingerprint the selected
source ID or selected variant hash. Switching sources on the same catalog
therefore reuses equivalent artifacts, while a changed normalized graph causes
the existing `--check fingerprint.provisioning.json` gate to reject resume.
Tests cover both equivalent-source reuse and graph-digest invalidation.

## 9. Error handling

The implementation fails closed for:

- a missing or malformed candidate list;
- an unknown source ID or URL;
- a missing lock variant;
- a selected lock whose SHA-256 differs from `locks/manifest.json`;
- lock semantic-equivalence failure;
- a lock that is stale against `pyproject.toml` for its own source;
- mutation of the canonical lock or repository worktree during sync;
- exhaustion of all reachable candidates.

Diagnostics name the source, lock path, failing command, and the documented
recovery step. The new pitfall entry follows the repository's required
`Symptom -> Root Cause -> Fix -> Verify` structure, and AGENTS.md receives only
an exception-table pointer rather than an inline fix.

## 10. Test and verification matrix

Implementation follows TDD. Required behavioral coverage is:

1. **Global-index pollution:** with inherited Tsinghua/Aliyun uv variables, no
   pre-existing `mirrors.json`, and a deliberately stale `mirrors.env`, the
   orchestrator consumes the `mirrors.json` generated in the current run,
   selects only its controlled candidate, and completes strict sync.
2. **Fallback order:** fake uv fails PyPI and Tsinghua downloads, succeeds on
   Aliyun, and the recorded attempts are exactly `pypi -> tuna -> aliyun`.
3. **No silent unlock:** every sync command includes `--locked`; no test path
   accepts `--frozen` or a regenerated root lock.
4. **Repository cleanliness:** canonical `uv.lock` hash and tracked status are
   unchanged before and after success and all-source failure.
5. **Lock equivalence:** versions, graph, markers, and artifact hashes match
   across all three variants; the canonical PyPI CDN and both measured mirror
   prefixes are accepted, while an artifact outside its declared prefix and
   intentional mutation of each semantic class are rejected.
6. **Unknown source:** an unrecognized candidate fails before uv execution.
7. **Environment restoration:** all inherited uv variables are byte-for-byte
   restored after success and failure, including absent versus empty values;
   an external uv config file cannot affect the selected registry.
8. **Fingerprint behavior:** changing only the selected equivalent source keeps
   the provisioning fingerprint stable; changing the normalized graph digest
   invalidates resume.
9. **Network-dependent manual acceptance:** on the target machine, each
   currently reachable PyPI, Tsinghua, and Aliyun source passes its matching
   `uv lock --check` and isolated `uv sync --locked --all-groups` path. A source
   that is genuinely unreachable is recorded as SKIP, not an automated-suite
   failure; fake-source tests remain the deterministic fallback acceptance.
10. **Regression:** focused tests, the reproduction harness, the full Python
   suite, PowerShell parse checks, and `git diff --check` pass.
11. **Acceptance continuation:** `hip-smoke-10` resumes from the failed Python
    environment stage, produces its complete evidence pack, and is reviewed by
    an independent subagent before the full-1651 step begins.

## 11. Expected files

Implementation is expected to touch only the minimum relevant set:

- `uv.lock` (read and hash as the canonical baseline; do not modify it);
- `locks/uv.tuna.lock`;
- `locks/uv.aliyun.lock`;
- `locks/manifest.json`;
- `scripts/generate-uv-lock-variants.ps1`;
- `scripts/verify_uv_lock_variants.py`;
- `scripts/detect-mirrors.ps1`;
- `scripts/reproduce.ps1`;
- `.gitignore` (generated `mirrors.json` only);
- focused tests under `tests/`;
- `docs/pitfalls.md`, `README.md`, and the AGENTS.md exception lookup row;
- evidence-pack/fingerprint code only if required to store the environment-lock
  record described above.

Unrelated server, inference, scoring, and metric behavior is out of scope.
