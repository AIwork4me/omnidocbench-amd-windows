# v1.6.1 Stabilization Design

## Goal

Stabilize the v1.6.1 release candidate on the real AMD Windows host, prove the
fresh HIP startup path, regenerate provenance-bound full-set evidence, and make
the release gate executable. Preserve the validated-resumed label unless a
separate fresh-checkout full inference is actually performed.

## Current evidence

- The clean branch baseline at `298a87e` passes all 307 tests.
- The full 1651-page prediction tree independently passes the strict gate at
  1649/1651 usable pages, 0.998789 coverage, with only the two allowlisted
  peg-native failures.
- The stored scores clear every formal threshold, but the evidence directory
  predates the v1.6.1 phase fingerprints and metric provenance sidecars.
- `release-gate.ps1 -Tag v1.6.1` fails before its first declared check because
  the raw multi-line `pyproject.toml` text is matched with a single-line
  anchored regular expression.
- The committed server workaround uses WMI to avoid an inherited redirected
  output pipe. The colleague's candidate instead removes the pipe at its
  source in `Invoke-ReproNative` and restores the normal hidden
  `Start-Process` wrapper launch.

## Approaches considered

1. **Remove native-output redirection at the orchestrator boundary
   (recommended).** `Start-Process -NoNewWindow -Wait -PassThru` preserves live
   console output and a deterministic exit code without creating an inheritable
   stdout/stderr pipe. The server setup can then use the ordinary hidden
   `Start-Process` launcher and retain a meaningful wrapper PID. This fixes the
   resource lifetime at its source and applies to all external stages.
2. **Keep redirection and detach only the VLM wrapper with WMI.** This is the
   committed state. It avoids the pipe for this one child, but introduces WMI
   availability/context assumptions and weakens the relationship between the
   PID file, process identity, and service lifecycle.
3. **Keep redirection and introduce a separate detached service manager.** This
   could model service lifetime explicitly, but it adds installation,
   permissions, cleanup, and recovery behavior that the project does not need.

Approach 1 is selected because it is the smallest root-cause fix and can be
guarded structurally plus proven by the real HIP smoke profile.

## Changes

### Release gate

Extract the project version with an explicit multiline regular expression and
fail with a controlled `RELEASE GATE FAIL` diagnostic when the declaration is
missing. A Windows test must execute the real script with a guaranteed-missing
tag and observe the normal missing-tag diagnostic; this test fails on the
current null-array exception.

### Native process invocation

`Invoke-ReproNative` will stop redirecting stdout/stderr to temporary files.
It will launch the child in the current console with `-NoNewWindow`, wait for
the direct child, and store `ExitCode` in `ReproLastExit`. The VLM setup will
return to a hidden `Start-Process -PassThru` wrapper and persist that wrapper
PID. Tests will guard the absence of redirected pipes and WMI launch code; the
real `hip-smoke-10 -ForceInference` run is the behavioral acceptance test.

## Validation gates

1. RED/GREEN tests for release version extraction and the native-launch source
   invariants.
2. The full 307-test suite passes in the isolated worktree.
3. An independent subagent reviews the task diff and test evidence.
4. A fresh HIP smoke reaches the human GPU confirmation gate, passes backend
   proof with no CPU fallback, produces 10/10 predictions, and completes both
   Windows and WSL scoring.
5. The formal full profile runs from a clean commit with `-Resume`; current
   prediction bytes must remain unchanged while both scoring provenance
   sidecars, phase fingerprints, strict summary, and artifact hashes are
   regenerated and verified.
6. v1.6.1 release notes describe verified/unverified devices, limitations, and
   evidence levels. The release gate passes before any publication step.

## Non-goals

- Do not claim clean-room or independent reproduction.
- Do not re-infer 1651 pages unless fingerprints or prediction-tree checks
  require it.
- Do not push, publish a GitHub release, or overwrite the colleague's dirty
  `main` checkout.
